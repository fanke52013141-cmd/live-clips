# 03 - 双环境执行方案（无 GPU 本机 / 有 GPU 家用）

- 日期：2026-11-12
- 前置文档：01-调研报告、02-基底选型与能力吸收方案
- 本文回答：**同一套产品，如何在「无 GPU 电脑」和「有 GPU 电脑（RTX 5080）」两种环境下都能完整跑通？**
- 总原则：**一套代码、两个执行档案（Profile）。GPU 是加速器，不是依赖项。** 任何阶段在无 GPU 时都有「CPU 本地」或「云端 API」两条退路；缺引擎时显式降级并提示，绝不出现不可用的死选项。

---

## 1. 架构：引擎抽象层 + 执行档案

```
管线各阶段（转写/分离/信号/选段/钩子/渲染）
        │ 只依赖抽象接口
┌───────▼────────────────────────────────────┐
│ EngineRegistry（引擎注册表）                 │
│  每阶段声明: 能力需求 + 可用引擎列表 + 降级顺序 │
│  启动时探测: CUDA 可用性 / 模型是否就绪 / API Key│
└───────┬──────────────────┬─────────────────┘
        │                  │
┌───────▼───────┐  ┌───────▼────────┐
│ Profile A      │  │ Profile B       │
│ cpu-cloud      │  │ gpu-local       │
│ 无 GPU 本机    │  │ 家用 RTX 5080   │
│ CPU + 云端兜底 │  │ 本地 GPU 优先   │
└───────────────┘  └────────────────┘
```

工程约定（沿用既有惯例）：
- Settings 为 frozen dataclass，Profile 整体替换切换，不改单字段
- 引擎探测失败 → 该阶段自动降级到下一候选，并在任务进度里**显式标注「已降级：XX→YY，原因」**
- 设置页只展示当前环境真实可用的引擎；不可用选项置灰并说明原因（或直接不展示），不做死按钮
- 全链路可用 mock 引擎跑通（测试/演示不依赖任何真实 Key 与 GPU）
- **进度可见性**：每个阶段上报数字进度（转写 12/128 分钟、候选 7 条、渲染 3/10 条、钩子生成第 2/4 步），SSE 推前端实时增长——长任务必须让人看到数字在动

## 2. 逐阶段双方案对照

### 2.1 ASR 转写（最吃算力的一环）

| | Profile A：无 GPU | Profile B：有 GPU |
|---|---|---|
| 首选 | **云端百炼 ASR**（qwen-audio-asr-flash 类，AutoClip 实测口径约 ¥0.1/小时音频） | **本地 faster-whisper large-v3**（中文正式发布级）或 **Paraformer GPU** |
| 次选 | 本地 CPU：faster-whisper small/medium + int8（2h 素材约需 20-60 分钟，可过夜批处理）；Paraformer CPU 可用但慢 | 云端 API 作为兜底（与 A 相同） |
| 词级时间戳 | 云端句级为主；需要词级时用本地 CPU whisper（word_timestamps）或 Paraformer 一体化时间戳 | large-v3 / Paraformer 均原生词级 |
| 热词 | 云端部分支持；本地 SeACo-Paraformer 热词 CPU 可跑 | SeACo-Paraformer GPU |
| 建议默认 | **云 ASR 为主**（快、准、便宜），本地 CPU 作离线兜底 | **本地 GPU 为主**（零边际成本、素材不出门），云兜底 |

要点：无 GPU 不等于不能用——**转写是「可外包」阶段**，音频上云的费用极低（一场 2h 直播约 2 毛钱），比 CPU 硬扛划算得多。隐私敏感素材才走本地 CPU 慢速档。

### 2.2 说话人分离（CAM++ / pyannote）

| | A：无 GPU | B：有 GPU |
|---|---|---|
| 方案 | CAM++ CPU 可跑（FunASR 原生支持）；pyannote CPU 很慢（长视频数分钟到数十分钟） | CAM++/pyannote GPU，分钟级 |
| 降级 | 默认关闭，用户显式开启才跑；或云端分离（如有） | 默认开启（连麦/访谈场景） |

### 2.3 信号层（弹幕 / 音频 / 视觉）

| 信号 | A：无 GPU | B：有 GPU |
|---|---|---|
| 弹幕密度/计权/反刷屏 | **纯 CPU 数学，无差别** | 同左 |
| 音频响度/RMS/峰值 | **纯 CPU（numpy/librosa），无差别** | 同左 |
| 笑声掌声事件 | SenseVoice CPU 可跑（轻量）；或云端 ASR 顺带事件标签 | SenseVoice GPU |
| 镜头边界 TransNetV2 | CPU 慢 → **降采样帧率（如 2fps）或跳过**，用 PySceneDetect 轻量替代 | 全帧率 GPU |
| 人脸/表情/运动 | CPU 抽稀帧（每 2-5s 一帧）轻量模型（YuNet 级）；或整体跳过 | 全量抽帧 + FER |
| 视觉多模态复核 | **云端 VLM API**（抽九宫格发云端，按张计费） | 本地 Ollama qwen-vl（零边际成本） |

要点：信号层设计成**「每路独立可开关」**，A 档案默认开「弹幕+响度+文本」三路（全是 CPU 轻量），视觉路默认关或降采样；B 档案全开。融合算法本身与 GPU 无关。

### 2.4 LLM 选段 / 评分 / 文案

| | A：无 GPU | B：有 GPU |
|---|---|---|
| 首选 | **云端 API**（DeepSeek/Qwen/豆包，一场直播几分到几毛钱，AutoClip 已验证） | 同左（质量优先） |
| 可选 | 本地 Ollama 小模型（4-8B）做初筛，云端精读（两级漏斗省钱） | 本地 7-14B 全量（隐私档，素材完全不出门） |

要点：**选段阶段两个环境无本质差异**——LLM 本来就走 API，这是整条管线对无 GPU 最友好的部分。

### 2.5 钩子工坊（L1-L4）

| 钩子级 | A：无 GPU | B：有 GPU |
|---|---|---|
| L1 文字贴片 | LLM 写句 + ffmpeg drawtext/ASS，**纯 CPU，无差别** | 同左 |
| L2 TTS 配音 | edge-tts（云端免费）/ 云 TTS API | 同左；可选本地 CosyVoice GPU（音色克隆） |
| L3 B-roll 生图 | **云端生图 API**（按张计费，几分~几毛/张） | 本地 SD/生图模型，或云 API |
| L4 文生/图生视频 | **仅云端 API**（即梦/可灵/Seedance，按秒计费；本地 CPU 生成视频不现实，直接不提供该选项） | **本地 Wan2.1 图生视频**（5080 16GB：GGUF 量化适配，SageAttention 走 KJNodes 节点方式）+ 云 API 双轨 |

要点：
- A 档案的 L4 走云 API 完全可行（商业工具也都这么干），只是按条付费；**只对爆款分 top 候选启用 + 人工确认**控制成本
- B 档案的本地生成是「零边际成本 + 素材不出门」的私有化卖点
- 5080 注意事项（既有经验）：Blackwell sm_120 需 torch≥2.7+cu128；xformers 不支持，用 SageAttention；全局 Triton 后端会让 Wan 系黑屏，必须走 KJNodes 节点方式；显存不够降 GGUF Q4_K_M

### 2.6 切割 / 渲染 / 编码

| | A：无 GPU | B：有 GPU |
|---|---|---|
| 切割 | ffmpeg 精确切割（重编码 x264 CPU），2h 素材出 10 条约几分钟~十几分钟 | NVENC 硬件编码（5080 支持），数倍加速 |
| 无损直拷 | 关键帧对齐时 stream copy，**两环境都秒级** | 同左 |
| 字幕烧录/贴片 | CPU libass/drawtext，无压力 | 同左（或 NVENC） |
| 响度归一/降噪 | CPU 音频滤镜，无压力 | 同左 |

要点：渲染不是瓶颈——切片输出总量小（10 条 × 1 分钟），CPU x264 完全够用；NVENC 是锦上添花。

## 3. 两个档案的默认配置总表

| 阶段 | Profile A（cpu-cloud，本机默认） | Profile B（gpu-local，家用默认） |
|---|---|---|
| ASR | 云百炼（词级需求→本地 whisper int8） | 本地 faster-whisper large-v3 / Paraformer |
| 说话人 | 关（可选 CAM++ CPU） | 开（CAM++ GPU） |
| 弹幕/响度信号 | 开 | 开 |
| 音频事件 | SenseVoice CPU 或云标签 | SenseVoice GPU |
| 视觉信号 | 关/降采样（PySceneDetect 替代） | 全开（TransNetV2+人脸+表情） |
| 视觉复核 | 云 VLM | 本地 Ollama qwen-vl |
| LLM 选段 | 云 API（+本地小模型初筛可选） | 云 API（隐私档→本地 14B） |
| L1/L2 钩子 | CPU + edge-tts | 同左（+本地 CosyVoice 可选） |
| L3/L4 钩子 | 云生图/生视频 API | 本地 Wan2.1 + 云 API 双轨 |
| 渲染 | x264 CPU + 无损直拷 | NVENC + 无损直拷 |
| 素材隐私 | 音频/抽帧上云（可切全本地慢速档） | 可 100% 本地（Ollama+本地 ASR+本地生成） |
| 单场 2h 直播边际成本 | 约 ¥0.3-1（ASR+LLM，不含 L4 生成） | 电费级（云 API 兜底时同 A） |

> 成本为公开口径估算（AutoClip 实测 + 百炼定价口径），非承诺值；L4 生成钩子按条另计（云 API 每条数毛~数元级，取决于模型与抽卡次数）。

## 4. 切换与同步机制

1. **一个仓库、一份配置目录**：`profiles/cpu-cloud.yaml` 与 `profiles/gpu-local.yaml`；启动参数或设置页一键切换（整体替换 Settings）。
2. **自动探测 + 显式覆盖**：启动时探测 CUDA/模型/Key，推荐档案；用户可手动锁定（例如家里机器也想走云 ASR 对比质量）。
3. **模型缓存分离**：本地模型目录可配置（本机只下 CPU 用的小模型，5080 机器下 large-v3/Wan GGUF），避免无 GPU 机器误下几十 GB 权重。
4. **任务可迁移**：项目/任务/转写缓存都是文件+DB，本机做一半的项目（如已转写）可拷到家里机器继续跑 GPU 阶段——转写缓存按「源文件指纹+引擎+参数」键控，换引擎自动失效重跑，不会串档。
5. **降级透明**：任何阶段降级都写进任务回执（clips.json 式审计），前端进度条旁标注，不静默。

## 5. 验收分工（沿用既有惯例）

| 环境 | 验什么 | 怎么验 |
|---|---|---|
| 本机（无 GPU） | **全链路正确性**：mock 引擎跑通每一阶段；真实小样本走 cpu-cloud 档案出片；降级路径（断网/无 Key/无模型）逐条触发并确认提示 | 全量测试（pytest+前端+tsc+构建）+ 人工走查审核台；进度数字实时增长可见 |
| 家用（5080） | **GPU 效果与性能**：large-v3 中文错字率对比云 ASR；本地 Wan 钩子画质/一致性；NVENC 速度；SageAttention/KJNodes 链路 | 同脚本 A/B（云 vs 本地），人拍板后才改默认档案；GPU 执行层改动不在本机盲改 |

**开发顺序不受 GPU 影响**：P0-P2 全部功能（ASR 集成/选段/双区间/信号/钩子 L1/合规/剪映草稿）在本机 cpu-cloud 档案即可完成开发与验收；P3 的 L4 生成钩子先用云 API 在本机开发，本地 Wan 引擎适配留到 5080 机器做——两档案共用同一接口，届时只是注册一个新引擎。

## 6. 对 02 号方案的影响

- 02 的 P0-P4 批次与依赖**不变**，仅每批验收拆成「本机 cpu-cloud 必验 + 5080 gpu-local 选验（涉及 GPU 引擎时）」
- 新增一个 P0 子任务：**EngineRegistry + Profile 机制**（这是双环境的地基，必须在集成第一个引擎前就位）
- 风险表补充：云 ASR/生成 API 的 Key 与计费管理（真实计费操作先说明再执行）；无 GPU 机器禁止下载大模型权重的默认保护
