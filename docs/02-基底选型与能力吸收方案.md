# 02 - 基底选型与能力吸收方案

- 日期：2026-11-12
- 前置文档：《01-直播切片开源项目调研报告》
- 本文回答三个问题：**以哪个开源项目为基底？吸收其他项目的什么能力？怎么吸收、好处是什么？**
- 证据口径：许可证与仓库结构已逐一抓取 GitHub 仓库页核实（AutoClip / openclip / live-mixer 为当日页面实测；FunClip / hotclip 许可证来自 README 声明）；星数标注实测来源。未核实项明确标注。

---

## 1. 结论（一句话版）

**以 AutoClip（MIT，10.4k★）为基底**，代码级集成 FunClip 的中文 ASR 引擎与 openclip 的边界复审流程，吸收 live-mixer 的「粗选/精修双区间」工作流与剪映草稿链路；**hotclip 只吸收思路、不抄代码**（AGPL-3.0 传染性与技术栈双重原因），把它的弹幕信号、钩子手法、合规设计、数据回流用我们自己的代码重实现——这四块恰好是 AutoClip 没有、而直播切片最需要的能力，也是我们的差异化空间。

## 2. 选型评估框架

选基底不是选「功能最多的」，而是选「改得动、敢商用、长得大」的。七个维度：

| 维度 | 为什么重要 |
|---|---|
| 许可证 | 决定能否闭源商用、能否混入其他代码（AGPL 一票否决闭源路线） |
| 技术栈匹配 | 我们团队是 Python(FastAPI) + React/TS + ffmpeg 栈（duo-podcast 验证过），换栈=重写 |
| 管线完整度 | 基底应覆盖「转写→选段→切割→包装→审核」主干，缺的才需要补 |
| 活跃度与社区 | 停更项目=自己养全部代码；高星=有人帮你踩坑 |
| 代码可读/可改 | 单体脚本好读但难扩展；过度工程难读但好扩展，要平衡 |
| UI 形态 | 决定交付形态（桌面/Web）与审核台改造成本 |
| 与产品理念的契合 | 「AI 出候选、人终审」必须是基底的既有交互，而不是我们硬塞 |

### 决策矩阵

|---|---|---|---|---|---|---|---|

## 3. 为什么是 AutoClip（论据）

以下全部来自当日抓取的仓库页与 README：

1. **许可证干净**：MIT，可闭源商用、可混入其他 MIT/Apache 代码，无传染负担。
2. **技术栈与我们完全同构**：backend（Python/FastAPI+Celery+Redis）+ frontend（React）+ src-tauri（桌面壳）+ Docker Web 部署 + CLI/MCP。duo-podcast 的 FastAPI+React 经验、frozen Settings、ffmpeg lavfi 夹具、mock 全链路验证方法可直接复用。
3. **管线主干完整且经过真实素材验证**：下载→转写（作者字幕/本地 Whisper/SenseVoice/云端百炼可选）→LLM 选段打分→句边界切割→**人物取景竖屏重构**→字幕/封面/标题/话题→ZIP 发布包。README 给出实测：1h43m 素材 7.5 分钟出 10 条、文字模型费用 ¥0.09；2h52m 中文素材 29.5 分钟、¥0.20。**成本工程已被验证**，这是我们自己从 openclip 起步要重踩的坑。
4. **「AI 初稿、人终审」是既有交互**：每平台至多 10 条合格片段+备选池，逐条预览/下载/进编辑器手改——与我们的产品理念天然一致，不用改造交互哲学。
5. **平台方言已内置**：抖音/小红书访谈式、TikTok/Reels/Shorts 满屏播客式、B站/YouTube 横版；字幕文案语言按平台。这是切片软件最琐碎也最值钱的部分。
6. **工程文档异常齐全**：仓库含 DESIGN.md、ROADMAP.md、HANDOFF.md、AGENTS.md、CLAUDE.md、CHANGELOG、benchmarks/、docs/research/（含《选对瞬间，而不是堆特效》的播放量驱动因素研究）、成本口径文档 COST_PER_VIDEO.md、隐私说明 PRIVACY.md。**它自己的协作惯例（HANDOFF/编号文档/Agent 指引）和我们团队几乎一样**，接手成本低。
7. **三种交付形态共存**：桌面（Tauri，Win/macOS 安装包自带 Python+FFmpeg）、Docker Web（localhost:3000）、CLI/MCP（`autoclip produce xxx.mp4 --platform douyin`）。我们先做 Web 工作台，桌面壳后置，不被 Tauri/Rust 绑架。
8. **社区动能**：10.4k★、1.8k fork、1297 commits、14 open issues / 20 PRs，个人维护但更新频繁（2026-11-10 仍有 push，API 实测）。上游修 bug 我们可以持续合并。

**AutoClip 的短板（=我们要吸收别人来补的清单）**：
- 中文 ASR 默认 Whisper base，中文错字率高于 Paraformer；无热词、无说话人分离 → **补 FunClip**
- 纯文本选段，无弹幕/音频/视觉信号 → **补 hotclip/douyin-living 思路**
- 无原生钩子手法（cold-open/flash-forward）、无文字钩子贴片 → **补 hotclip 思路 + 自研钩子工坊**
- 无剪映草稿导出（只有 ZIP 成片包）→ **补 live-mixer/capcut-mate 链路**
- 无授权台账/违禁词/AIGC 标识/判搬运自评 → **补 hotclip 合规思路（自研）**
- 无发布数据回流 → **补 hotclip 反馈思路（自研）**
- 边界质量靠一次 LLM 输出 → **补 openclip 的 judge→repair→rejudge 复审环**

## 4. 能力吸收清单（吸收什么 / 怎么吸收 / 好处 / 代价）

吸收分三个层级，**层级由许可证和栈决定，不是由喜好决定**：

- **L1 代码级集成**：MIT/Apache 且 Python 栈，直接引入或移植代码
- **L2 思路级重实现**：AGPL 或异构栈，读文档/观察行为，用自己代码重写（不复制源码，避免版权与传染问题）
- **L3 生态工具对接**：独立进程/API 调用，不进代码库

### 4.1 FunClip（MIT）→ L1：中文语音基建

| 吸收项 | 怎么吸收 | 好处 |
|---|---|---|
| Paraformer-Large 中文 ASR + 词级时间戳 | 以 FunASR 为依赖替换/并列 AutoClip 的本地 Whisper 选项，按语言路由（中文 Paraformer、英文 Whisper，openclip 已验证此路由模式） | 中文错字率显著下降；词级时间戳让切点精确到词（AutoClip 目前句级） |
| SeACo-Paraformer 热词 | 项目级热词表（主播名/商品名/黑话），转写时注入 | 直播切片刚需：商品名错一个字，LLM 选段和字幕全错 |
| CAM++ 说话人分离 | 转写阶段可选开启，句子打 spk 标签进 LLM 上下文 | 连麦/PK/访谈场景选段不断章取义；字幕按人上色 |
| SenseVoice 情绪/音频事件 | 作为可选 ASR 引擎，顺带输出笑声/掌声/情绪标签 | **免费获得一路音频信号**，不用单独训检测器 |

代价：模型下载约 2GB 起；CPU 可跑但 GPU 更快（本机 mock/CPU 验证，5080 实测加速，沿用我们的验收惯例）。
注意：FunClip 代码 MIT，但模型权重各有条款，商用前核对 Paraformer/CAM++ 权重许可（ModelScope 页面）。

### 4.2 openclip（MIT，~5K 行）→ L1：选段质量流程

| 吸收项 | 怎么吸收 | 好处 |
|---|---|---|
| **deep-optimize 复审环**：judge（能否独立成段）→ repair（修边界）→ rejudge | 移植其 prompts/ 模板与流程编排到 AutoClip 选段后处理，做成可选开关 | 直接提升「切口自然、独立可懂」——切片废品率的最大来源就是半截话；官方口径 60min 视频额外 3-6 分钟，成本可控 |
| `--user-intent` 自然语言定向 | 选段 API 加 intent 参数进 prompt | 运营可以说「只要讲安装售后的」「只要和XX连麦的冲突」，B 端刚需 |
| background.md 背景上下文 | 项目级背景文件（主播信息/术语/账号定位）注入分析 | 同一个 LLM，懂行与不懂行选段质量差一档 |
| 边界归一化（句边界优先、其次停顿） | 与 AutoClip 既有句边界切割合并，升级为「句→词→镜头」三级吸附 | 切点不拦腰截断 |
| 说话人参考音频→姓名映射 | 借鉴其 extract_reference 工具思路（10-30s 参考音频） | 字幕直接标「主播:」「嘉宾:」而不是 S0/S1 |

代价：极小。openclip 代码量小、MIT、提示词即配置，是**性价比最高的吸收源**。它的存在本身证明 AutoClip 管线可以被轻量复刻——我们集成它的流程而不是它的壳（Streamlit 不进产品）。

### 4.3 live-mixer（Apache-2.0）→ L1 数据模型 + L3 剪映链路

| 吸收项 | 怎么吸收 | 好处 |
|---|---|---|
| **clips0（AI 粗选）/ clips1（人工精修）双区间模型** | 在 AutoClip 项目模型上加两层区间字段：AI 产出永远写 clips0，人工修改写 clips1，导出只认 clips1 | 把「AI 候选 vs 人工决定」变成**数据结构**而不是 UI 约定——可审计、可回滚、可统计 AI 采纳率（这是我们产品理念的工程化落点） |
| 素材库管理（URL/m3u8/本地，探测时长分辨率） | 参考其 live-materials API 设计扩展 AutoClip 输入层 | 从「单视频工具」变「工作台」，B 端形态的基础 |
| 系统提示词 CRUD（llm-system-prompts） | 提示词做成可管理资源而非硬编码 | 不同直播类型（带货/娱乐/知识）不同选段策略，运营可自己调 |
| **capcut-mate 剪映草稿服务** | L3：Docker 起 capcut-mate，切片结果转剪映草稿格式 | **不自研编辑器**：AI 粗剪→剪映精修接力，省掉整个赛道最重的 UI 工程量；剪辑师零学习成本 |
| 异步任务+轮询/SSE 进度 | AutoClip 已有 Celery，对齐其任务阶段划分即可 | 工程对齐，无新增成本 |

代价：capcut-mate 许可证**未核实，集成前必查**；剪映草稿格式随剪映版本变化，需要维护适配层。live-mixer 本体是 Go，不搬代码，只搬模型与流程设计（Apache-2.0 允许搬，但栈不匹配没必要）。

### 4.4 hotclip（AGPL-3.0）→ L2：只吸收思路，逐项自研重实现

**法律红线：不复制其源码进我们的代码库**（AGPL 对网络服务也传染）。读 README/文档/试用观察行为，用自己的 Python/TS 重写。以下每项都标注「它验证了什么」——这就是吸收的价值：**它替我们试错了产品方向**。

| 吸收项 | 它验证了什么 | 我们怎么重实现 | 好处 |
|---|---|---|---|
| **弹幕信号计权** | 礼物/SC/点赞比弹幕硬；单人刷屏要封顶；爆发有加成 | 解析录播姬 xml/抖音 jsonl，滑窗密度+高能词+互动计权+反刷屏，输出时间轴信号 | 观众逐秒投票是最强证据；AutoClip 完全没有这路信号 |
| **多信号共振** | 单路会骗人（音量高=BGM，弹幕高=刷屏），同秒共振才可信 | 信号融合层：Z-Score 标准化+加权+共振加成（数学方法参考 douyin-living 的公开描述） | 爆点查准率质变；带货/娱乐直播通吃 |
| **爆款分=同批相对排名** | 分数是排序器不是预言机；四维（钩子/结构/价值/热点）+每维一句理由 | LLM 评审输出四维分+理由，批内归一；弱片标「不建议发布」 | 用户信任感：可解释、可比较、不玄学 |
| **cold-open 高潮前置 / flash-forward 爆点闪现** | 原生钩子可自动化；定位失败宁可不做 | 在 clips1 确认后，LLM 定位片段内最强钩子句→重排到开头（词边界切割保证安全）；闪现版取 0.3-1s 高能画面 | 零成本钩子，完播率手法；README 称仅 0.04% 切片有视觉钩子=空白点 |
| **文字钩子贴片** | AI 悬念句烧开头 2s 上三分之一，写不出就不加 | LLM 生成悬念句→ffmpeg drawtext/ASS 贴片，避开主体 | L1 级自制钩子，OpusClip 默认开启的等价能力 |
| **LLM 只挑段、时间戳反查对齐** | 不让 AI 猜时间；导出前二遍对齐修正 | 我们继承 AutoClip 句边界+FunClip 词级时间戳，天然满足 | 切点可信 |
| **去气口三重判定** | 无词+低峰值+本地 VAD 无人声才剪，防吞人声 | ffmpeg silencedetect + ASR 词间隙 + VAD 三条件 | 口播/带货节奏紧凑化，不误删笑声尾音 |
| **合规四件套** | 变形度评分防判搬运；违禁词 lint；AIGC 显式+隐式标识；分发留证包 | 自研：二创增量自评（取景/跳剪/贴片/钩子加权）、词表 lint、标识注入、源片区间台账 | 切片分销客户的生死线，B 端付费理由 |
| **发布数据回流 + 一片多版 A/B** | 同平台/72h 窗口/每版≥500 播放才比较；只报方向不报因果 | 内容 ID+CSV 导入对账，归纳高低表现共性反哺选段 prompt | 越用越准的飞轮；矩阵客户刚需 |
| **字幕安全区预览** | 九平台 UI 遮挡实测遮罩 | 前端叠遮罩层（公开可观察的平台 UI 尺寸） | 字幕不被点赞栏吃掉，细节专业感 |
| **舒适优先竖屏取景** | 能锁机位就锁，不追脸晃；持续漏检才回正 | AutoClip 已有人物取景，借鉴其「锁定优先」策略调参 | 观感稳定，减少晕动 |

代价：这是工作量最大的一块（估计占自研总量 60%+），但**每一行都是我们自己的 MIT/闭源资产**，且构成对 AutoClip 上游的差异化壁垒。

### 4.5 其他单点吸收

| 来源 | 吸收项 | 层级 | 好处 |
|---|---|---|---|
| video-clipper（MIT 声明见 README） | 硬规则清单：词边界切割、30ms 淡入淡出防爆音、字幕最后烧、转写缓存、源文件永不修改、13 类切片类型策略 | L2（规则是通用工程常识，按其文档落成我们的 lint/测试） | 少踩坑；13 类型 prompt 策略可参考重写 |

| NarratoAI / MoneyPrinterTurbo（生成赛道） | 「文案驱动画面」管线：钩子文案→文生图→图生视频→拼接 | L3（接生成 API） | 你的 L4 生成式钩子的现成范式 |
| VideoLingo（19.2k★，MIT 未核实） | 字幕切分/翻译/配音对齐 | L3（出海阶段再评估） | 切片出海一步到位 |
| social-auto-upload / biliup | 多平台发布、直播录制 | L3（P3） | 不自己养平台协议逆向 |

## 5. 目标架构（基底 + 吸收模块）

```

                    │  钩子工坊(L1贴片/L2 TTS/L3-4生成) · 合规四件套 │
                    │  弹幕/音频信号融合 · 数据回流 A/B · 发布包     │
                    └───────────────┬────────────────────────┘
                                    │ 改造/扩展
┌───────────────────────────────────▼──────────────────────────────────┐
│ AutoClip 基底（MIT, fork）                                            │
│ FastAPI+Celery 任务管线 · LLM 选段打分 · 句边界切割 · 人物取景竖屏重构    │

└──┬──────────────┬──────────────┬──────────────┬─────────────────────┘
```

## 6. 分批实施计划（含依赖与验收）

沿用我们的惯例：每批全量测试绿了再进下一批；GPU 相关（本地 ASR 加速、生成钩子）本机 mock/CPU 验链路，效果留 5080 实测。

**P0：fork 跑通 + 中文基建（依赖：无）**
1. fork AutoClip，Docker Web 形态本机跑通示例项目；读 DESIGN.md/管线代码，产出《上游架构笔记》
2. 集成 FunASR：中文路由 Paraformer + 热词表 + CAM++ 可选；保留 Whisper 英文路由
3. 用一段真实中文直播回放（ffmpeg lavfi 造测试夹具 + 真实素材人工验收）跑全链路
- 验收：2h 中文直播出 ≥10 条候选，字幕错字率主观可接受，切点无半词；全量测试绿

**P1：选段质量 + 双区间工作流（依赖：P0）**
1. 移植 openclip deep-optimize 复审环 + user-intent + 背景上下文
2. 数据模型加 clips0/clips1；审核台支持逐词微调切点、改标题、勾选/否决
3. 弹幕文件接入（录播姬 xml/抖音 jsonl）+ 音频信号（SenseVoice 事件/响度峰）→ 融合注入 LLM 上下文
4. 四维爆款分（批内归一）+ 每维理由 + 弱片标记
- 验收：同一素材开/关信号与复审环 A/B，人工采纳率提升可量化；AI 改动全部可追溯

**P2：钩子 + 成片质量 + 剪映接力（依赖：P1）**
1. cold-open / flash-forward（定位失败自动跳过）+ L1 文字钩子贴片
2. 去气口三重判定、30ms 淡化、响度归一 -14 LUFS、字幕安全区预览
3. capcut-mate 剪映草稿导出（先核实其许可证）
4. 合规四件套 v1：违禁词 lint、AIGC 标识、授权台账、源片区间留证
- 验收：成片可直接发抖音；剪映打开草稿时间轴完整；合规项逐条可演示

**P3：生成式钩子工坊（依赖：P2，你的核心差异化）**
1. L2 TTS 钩子（edge-tts 起步；克隆音色走授权流程）
2. L3/L4：钩子文案→文生图→图生视频（先接即梦/可灵/Seedance API；本地 Wan 留私有化选项），仅 top 候选启用、人工确认后合成、自动 AIGC 标识
3. 一片多版（不同钩子角度）+ 发布数据 CSV 回流对账 + 方向性 A/B 报告
- 验收：生成钩子与正文兑现一致性人工评审；成本报表（每条钩子费用）；回流对账无歧义行

**P4：工厂化（依赖：P3，按商业需求启动）**
- 录播目录监听/开播检测、三档审核闸门、发布泵匀速多账号（social-auto-upload）、数据战报

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| **AGPL 污染**（hotclip 代码混入） | 制度性隔离：hotclip 只读文档/试用，重实现时不打开其源码对照抄写；代码评审加许可证检查项 |
| 上游 AutoClip 快速演进导致 fork 漂移 | 定期合并 upstream；我们的扩展尽量做成独立模块（信号层/钩子层/合规层），少改上游核心文件；改动台账化（沿用 HANDOFF 惯例） |
| 个人维护项目断更 | MIT 意味着断更也不影响我们继续用；P0 架构笔记确保核心管线有人能接手 |
| capcut-mate / 模型权重许可未核实 | P2 前逐项核实，未核实不集成 |
| 剪映草稿格式变动 | 适配层独立模块+版本探测；ZIP 成片包始终保留为兜底导出 |
| Tauri 桌面壳（Rust）不熟 | 先交付 Web 工作台（Docker），桌面壳 P4 后再评估，必要时换 Electron 壳复用 React 前端 |
| 本机无 GPU | ASR 用 CPU int8/云端百炼兜底；生成钩子走 API；效果验收留 5080（既有惯例） |
| 平台判搬运/AIGC 政策 | 合规四件套内置；生成钩子只做「引子」，正文必须真实素材；单场限产提示 |

## 8. 备选路线（如果不选 AutoClip）

- **路线 B：openclip 为基底**（MIT、5K 行、完全读得懂）。适合「只要选段引擎、UI 全部自研」的极简路线。代价：竖屏取景、平台包装、成本工程、桌面分发全部自己造——等于把 AutoClip 一年踩的坑重踩一遍。**仅当我们决定做纯 B端 API 服务（不要 C 端界面）时才值得**。
- **路线 C：hotclip 为基底**。功能最全、最接近成品，但 AGPL-3.0 要求衍生作品开源（含 SaaS 形态），且 Electron/TS 栈与我们不符。**只有当我们决定整个产品开源（AGPL）时才考虑**——那等于放弃闭源商业化。
- **路线 D：live-mixer 为基底**。Apache-2.0 干净、B 端工作流最正统，但 Go+Qt 栈、19★ 社区太小，ASR 绑豆包云。**吸收它的设计，不继承它的代码**。

综合：路线 A（AutoClip 基底）在许可证、栈匹配、管线完整度、社区、理念契合五项上唯一全绿。
